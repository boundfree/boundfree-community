# 通用设备采集候选能力与开发入口

通用设备接入正在 `feature/bfsp-acquisition` 分支开发，采用“设备适配 → 规范信号对象 → 显示/分析/录制”的边界。它是开发候选能力，不代表既有 Beta 安装包已经增加真实设备支持。产品版本仍由 `version.json` 管理，BFSP 候选线协议为 1.0，现有文件边车 IPC 版本保持不变。

## 1. 当前入口和支持边界

- 菜单栏“设备 → 连接设备”进入设备菜单的连接管理窗口。设备连接窗口继承应用现有浅色/深色主题、配色和原生控件，默认展示 RT-BCI 与保存记录，BFSP TCP 和模拟设备放在“高级连接方式”内。显式连接成功后自动接收信号、切到波形浏览，并在主窗口现有的同一个 `WaveformWidget` 中显示；模拟来源始终明确标记。
- 进程内模拟器与独立 Python TCP 模拟器用于验证共同模型、协议、控制和录制。模拟结果不证明硬件采集或生理信号效果。
- RT-BCI Wi-Fi 已有候选适配器：HTTP 控制、电脑监听 TCP 接收原始帧、8/16 通道解码，进入相同 SignalHub、显示和录制链路。真实模块兼容性仍待实机验收。
- SerialPort 为可选编译能力；缺少 Qt SerialPort 时离线和 TCP 仍可构建。USB Bulk、BLE、UDP、厂商 SDK 和其他设备适配尚需各自实施与验收。
- 原始数据类型与单位保留；实时显示按标定换算、抽稀，录制保存原始数值。实时和文件窗口进入同一处理与分析工具；实时默认连续因果滤波，也可显式选择窗口零相位。ICA 可分析固定片段，或将已检查的设备模型持续应用于新样本；不逐帧重新拟合。
- 单设备工作流先行；当前 Native TCP 客户端在握手中声明最多16条流、每流256通道的接收上限，区别于线协议的64流/4096通道总上界。主工作台每次选择一条流，以该流自身的样本序号、采样率和全部通道构建完整窗口；旧设备概览的有界包络最多16通道，不作为分析输入。录制保存已接纳流的全部通道。多流波形不构成跨时钟同步证据，多设备对齐、硬件同步和长时间性能以独立验收为准。
- 目前贯通数据缺口事件；RT-BCI 按 OpenBCI 接收序号构建本地样本索引，8 位输出计数仅用于诊断。一般触发/质量事件、动态适配器注册/发现和其他设备计数器仍待实施。时钟测量和拟合已有独立模型与测试，尚未自动执行 TCP 周期同步或将映射写入录制；`clock-mappings.jsonl` 目前可为空，不能据此声称已经同步。

协议真值：[BFSP 候选规范](bfsp-protocol.md)、[连接与适配器规范](bfsp-transports.md)、[机器契约与向量](../contracts/bfsp/README.md)。

设备连接统一在设备菜单的连接管理窗口完成，连接后直接进入波形浏览。首次进入“脑电 / 眼电 / 肌电分离”自动准备设备建模片段，页内不提供连接或文件打开入口，文件/教学输入在“文件”菜单；可“重新获取建模片段”，复用适配后的完整原始采样窗口；即使主波形正在查看文件或已暂停查看，也能独立获取设备缓存。多流先选择一条流；最近最多 10 秒中取至少 5 秒的最长连续区间，不跨缺口拼接。取样后固定输入，再次取样才替换结果；同一数据流可保留通道用途。该入口使用 float32 投影快照，保留实际单位、来源时间和模拟标记，采集与原始录制继续。操作与精度边界见 [分析说明](analysis-guide.md#进入脑电--眼电--肌电分离)。

设备连续 ICA 入口位于分离页顶部：设备连接窗口连接 → 波形浏览 → 分离页自动准备片段（不足 5 秒时自动等待并可取消）→ 设置通道用途 → 建立分离模型 → 人工检查并确认 → 开始连续 ICA。固定模型处理同一设备的新样本，支持 250/500 Hz、设备与输出率一致且陷波关闭；重连/换配置后停止旧模型。原始采集、录制和波形暂停独立；连续结果当前仅显示，片段导出保持建模输入。操作与限制见 [设备连续 ICA](analysis-guide.md#设备连续-ica)。

## 2. 基本操作与录制语义

当前配置界面提供250/500/1000 Hz三个采样率入口；BFSP TCP 仅在对端声明单组可配置能力时启用，并由能力校验与设备配置回读确认。RT-BCI 的 HTTP 请求值不代表 ADC 已读回确认，见第 3 节。其他组、任意配置字段、带宽准入与一般设备发现尚待实现；只读设备可按已有配置采集。

配置部分生效或配置版本冲突时，当前客户端结束该连接的操作并保留设备错误原因，禁止继续开始采集；重新连接后读取设备实际配置。自动恢复此类配置事务尚未实现。采集中暂时锁定参数与设备只读能力分别提示。

界面中的连接操作包含连接成功后的自动接收与波形显示，录制仍需单独开始。“停止采集”可暂停接收，再在“采集设置”中修改采样参数；修改后先应用，再继续采集。录制、接收与暂停查看分别管理，暂停查看或切换工作区不会停止接收和录制。控制器的底层连接接口本身仍不隐式启动采集。

实时波形上方的设备采集状态与显示操作分开排列：时间窗默认 2 秒，可选 0.25/0.5/1/2/5/10 秒；通道可选全部或单独一条，单通道使用整个绘图区。暂停查看固定当前已有的显示缓存，切换时间窗、通道或拖动都不停止采集/录制，回到实时跟随最新数据；重置视图恢复 2 秒、全部显示通道和纵向倍率 1，保留当前暂停状态。停止采集后保留最后波形，并明确显示已停止。顶部“操作说明”按钮提供全部快捷操作说明。

鼠标移至波形：Ctrl＋滚轮按预设档位缩放时间轴，实时状态保持右端跟随，暂停状态围绕指针位置缩放；Shift＋滚轮以当前数据中心缩放幅值（0.25～16 倍），普通滚轮滚动通道。点击波形获取焦点后，空格暂停/回到实时、＋/－缩放时间、0 重置；双击也可重置。暂停后左键拖动或左右方向键平移，移动限制在冻结缓存范围内。这些交互仅在设备波形激活时生效，文件工作区不继承其显示倍率。

大范围实时轴以 `count ×10⁶` 等显式单位倍率缩短刻度，小数单位按范围保留精度；百万基线上的微小变化仍保留可区分的上下界。倍率仅改变标注/显示坐标，不修改原始数值、波形极值、录制、设备通道或采样配置。完整信号窗口先处理和分析，再由绘图层做有界极值抽稀；抽稀结果不能回流处理链；样本时间仍不构成 ADC 速率或跨时钟同步证据。

录制在已有采集流中途开始时，保留原样本序号并记录该次录制的起点；不将录制前的样本误报为丢失。停止录制关闭输入并保存已接纳数据，采集可以继续。停止采集会结束对应数据段，并清算进行中的录制。

输出为新建的 `capture-<UUID>/` 目录，包含 `manifest.json`、`signals.h5`、`events.jsonl` 和 `clock-mappings.jsonl`。各流保留身份、原始编码、标定、时间和块索引；int24 无损符号扩展为 HDF5 int32，manifest 保留 original_dtype。

`complete` 表示文件正常封闭且未发现声明中的数据缺口；`partial` 表示成功封闭但存在缺口、中断或未录入样本；`failed` 不保证文件完整。`finalized` 与这些状态分开保存，不能把一次写入响应或 HDF5 flush 当成断电持久化保证。

录制完成后点击“查看录制”，或在“文件 → 打开设备录制文件夹…”选择完整的 `capture-<UUID>/` 目录。普通“打开数据文件…”也接受目录中的 `manifest.json` 或 `signals.h5`；ZIP 需先解压并保留配套文件。模拟器和真实设备使用同一回放入口，模拟来源会明确标示。尚未结束、缺少 manifest、空记录或校验失败分别提示原因，不修改原文件。

回放复用文件浏览的同一个波形、播放/暂停、进度拖动和时间窗控件，多流在“数据流”中分别选择，切换后沿用所选流进行读片。各流使用自己的名义采样率、逐通道单位和标定；int24/int32/float64 等原始数据保留在源文件中，显示投影仍使用已有 float32 IPC。原始 `count` 不会标成 µV，不强行拼接不同采样率/时钟的数据。记录起点按整数样本序号保留，回放时间相对该次录制起点、按声明速率计算，不构成硬件同步或真实 ADC 速率证明。

已知样本序号缺口保留时间间隔并断线显示，不补零；没有明确位置的未知缺口保留计数/状态，不猜测丢样位置。当前仅回放信号和缺口，尚未叠加一般事件或时钟映射。`partial` 记录中的已保存数据可以查看，不代表完整无丢样。读取按块验证 SHA256，过大的显示窗口提示缩短时间窗。采集记录与实时窗口共用原始/处理后选择、预处理、幅值、四类频谱分析、标注、分离快照和片段导出。原文件只读表示不写回原件，不限制工具。不同单位不可直接做平均参考或双极运算；无效滤波参数、连续样本不足或超出缓存范围时单独提示原因。

## 统一工作台的处理与导出

主界面保持原有左侧通道/预处理、中间波形、右侧分析、底部操作布局；窄窗口将波形与分析放入标签页。设备启停、原始录制、日志和查看操作集中在波形浏览与分离两页共用的底部操作栏；录制进度、保存路径和相关提示使用现有底部状态栏单行显示，长文本省略，悬停可查看完整内容，临时诊断优先显示，查看录制按钮留在操作栏；波形顶部只保留时间窗、自动幅值、幅值和标注模式。原始/处理后选择与执行模式收在左侧“信号预处理 → 高级设置”，流选择与来源说明在“通道”页，不重复占用波形顶部。原始/处理后选择共同决定波形、功率谱、时频图、频段趋势和相干性输入，分析始终读取完整样本。数据来源只决定取数方式和来源提示。

高级设置中的“滤波方式”提供“片段滤波”和“连续滤波”，下方随所选方式显示适用场景与影响。片段滤波适合查看文件，对当前连续片段执行零相位滤波，片段两端可能受影响；连续滤波适合实时采集，以因果方式处理新增样本，波形可能有时间偏移。这里的场景是选择建议，两种方式都可显式选择；只有选择“处理后波形”时，滤波才影响显示与分析。

连续因果模式保留滤波状态，只处理新增样本；切换采集段、参数或遇到缺口时重置对应状态。窗口零相位按完整连续片段执行，边缘行为与因果模式不同。暂停查看固定当前选区，后台接收、原始录制与连续处理继续。已知缺口以 NaN 断线，分析选择选区内最长有效连续片段，并显示实际分析区间；不跨缺口滤波或补零。

上方“脑电 / 眼电 / 肌电分离”工作区入口将当前原始选区的最长完整连续片段保存为临时 HDF5 快照，进入已有分离工具；不继承浏览滤波。该快照来自共享 float32 浏览投影，后续分离使用 float64 数组，不能恢复原始精度；直接在分离工作区打开原文件仍走原有 float64 读取入口。

原始设备录制直接订阅 SignalHub 中的原始 typed 块，不经过 DSP、显示缩放或导出。片段导出保存选定原始/处理后窗口及其单位、来源和参数。HDF5 保留缺口、显式时间和来源；CSV 附带 `.meta.json` 保存单位与来源，CSV/EDF 不支持有缺口的选区，需改用 HDF5。EDF 受物理范围限制，超出可表达范围明确拒绝。count 不会标成 µV；模拟标记在导出和再次打开后保留。普通文件重新录制的旧接口与设备原始录制分别保留。

实时窗口受 32 MiB 总预算和最多10秒历史限制，过大时提示缩短窗口；不把此限制包装成硬件吞吐承诺。一般硬件事件叠加、跨设备时钟同步与长稳性能仍单独验收。

## 3. RT-BCI Wi-Fi 使用

1. 点击菜单栏“设备 → 连接设备”，选择 RT-BCI。未加入设备热点时点击“打开 Wi-Fi 设置”，在系统中连接 `OpenBCI-RYTY`；没有互联网不妨碍局域网采集。
2. 返回应用后自动读取设备状态；型号兼容与唯一设备身份分别判断。连接后适配器从数据流自动识别通道数，模块报告仅用于诊断。16 通道须在上电前连接扩展板；之后插拔扩展板须断电重启。
3. 点击“连接并查看波形”后自动开始接收，在主波形区显示。默认名义采样率为 250 Hz；名称、名义采样率、端口、网卡、增益及参考电压收在“高级设置”中，按需展开。未知增益按 count 显示和录制，不把声明的标定当成设备确认值。
4. 波形页默认仅显示来源/状态、停止采集、录制和“更多设置”；设备设置、统计、暂停查看等在更多设置中。文件与设备使用同一个波形组件，保留每流的独立相对时间、缺口和各通道单位，不插值拼成单一采样率，也不因此声称同步。
5. 可随时再次打开设备管理，后台接收和录制继续；运行期间锁定切换目标、断开和配置。波形浏览一次展示一个来源：通过“文件→打开文件”重新选择文件，通过底部设备入口显示实时波形。切到设备后释放旧文件浏览缓存并异步关闭文件读取会话；不保留文件返回按钮或旧文件视图，迟到文件回读不会覆盖设备波形。

RT-BCI 的 POST 控制请求使用实机诊断日志已接受的 BrainFlow 参考封装：HTTP/1.0、`Host` / `Content-Length` 标准大小写、不附加 `Content-Type`。响应支持有界的 Content-Length、连接关闭定界与分块编码；超长、矛盾或截断响应失败后不会重发控制命令。只读 GET 与启停 GET 同样使用 HTTP/1.0；HTTP 默认时限与参考一致为 10 秒。

TCP 配置请求采用 `output=raw`、`delimiter=true`、`latency=10000`（微秒）。适配器滑动扫描 33 字节帧，连续三个 A0 帧头和 C0～C6 帧尾确认同步；字节错位后重新扫描并标记未知缺口，不主动删除 CR/LF 或其他 payload 字节。对齐流的解码保持 BrainFlow 参考行为，错位流则有意采用重同步，不再等同参考行为。`delimiter=true` 仅为发送给模块的配置字段。

识别使用最近 24 帧：计数均逐帧加一时判为 8 通道；相邻相同计数至少占 40%，且每个计数基本成对、其余递增时判为 16 通道。计数按 8 位回绕处理；干扰后继续累积，最多暂存 200 帧。设备不能上报已确认的通道数，Wi-Fi 模块 `num_channels` 也可能有误；识别基于适配器发送采样率命令后固件的 Wi-Fi 计数规律，不代表硬件确认。已接收到字节但 3 秒内无法识别，或达到识别上限仍不能判定时，会显示错误；可检查设备后重试，必要时在高级设置中选择强制通道数作为识别失败的后备。如果仍找不到有效帧，强制值也无法修复数据流。识别成功时，即使与强制值不同，也使用识别结果并给出非阻塞提示。完全没有收到字节时保持等待，可取消采集。

日志 `channel_selection` 记录模块报告、识别结果、来源及识别帧数/成对数；录制元数据记录 `requested_channels`（自动为 0）、`detected_channels`（后备时为 0）、`reported_channels`、`channel_layout_source`（`detected_from_wire` 或 `user_forced`）和 `channel_report_mismatch`。报告缺失时为 0，比较使用实际采用的布局。这些字段不表示设备确认，真实前后 8 路身份仍需已知输入逐路核对。

TCP 建立后按参考顺序发送 `~4`、`d`，最后发送界面选择的 `~6/~5/~4`；HTTP 接受不证明实际 STM32 完成配置。准备阶段不额外发送 `/stream/stop`。启动接口接受后开始接收，停流请求前暂停接收处理；暂时无数据只记录等待日志，不再用半个输出计数周期终止采集。真实 TCP 断开、控制请求失败或内存预算耗尽仍报告对应故障。

本机模拟器、BFSP TCP 与 RT-BCI 使用同一个 `AcquisitionDiagnosticLog`，在开始连接时自动创建日志，不需要点击“开始录制”。采集栏和“设备 → 打开日志”都可打开当前/最近会话日志的位置；Windows 会在资源管理器中选中当前 JSONL 文件，其他平台打开所在文件夹。停止采集、断开后仍保留入口和路径，采集中打开日志不停止接收或录制；尚无会话时打开统一日志目录。

日志默认写入系统应用数据目录下的 `BoundFree-Acquisition-Logs/`，不可写时尝试下载目录和临时目录。旧 `.9` 的 `BoundFree-RTBCI-Logs` 文件保留原位置，不删除或迁移。开发者/自动测试可用 `BF_ACQUISITION_LOG_DIRECTORY` 显式指定根目录；此覆盖为独占路径，无法写入时不回退，采集仍可继续。旧测试变量 `BF_RTBCI_LOG_DIRECTORY` 仅作为兼容别名。

统一 JSONL 顶层包含 `schema=1`、`time`、`kind`、`app_version`、`adapter`、`log_session_id` 和 `simulated`。本机模拟器明确为 true，RT-BCI 为 false，BFSP 握手前未知为 null，随后按能力和流描述报告；不同连接使用不同文件与 ID，停止和重启同一连接会在同一文件中记录多段启停。连接、配置、启停、错误、流统计与适配器特有的原始帧警告共用写入器；凭据键及常见凭据赋值文本脱敏。详情最多 8 MiB，另预留 64 KiB 生命周期摘要，超限时记录 log_limit 和累计丢弃事件数。诊断目录或写入失败不会终止采集。


实时波形默认开启逐通道自动缩放，以可视时间窗的实际变化确定纵轴范围，不再用直流偏置的百分比作为最小范围；百万 count 基线上的小幅变化也能显示。每两秒更新范围，保持原始数值和直流坐标，不修改录制或添加滤波。恒定输入仍显示直线，不制造波动。

统一日志约每秒生成各流的 `signal_stats`，统计前 16 个通道（并声明总数/实际统计数）的原始存储值最小/最大值、峰峰值、均值、标准差、变化次数，附原始 dtype、声明的物理单位、scale/offset 和流模拟标记。停止/关闭时保存未满一秒的尾部统计，SIM 与硬件规则相同。`flat=true` 仅表示该统计窗内值恒定；整型且声明有效 ADC 位数时，另统计达到相应整数上下限的比例 `rail_fraction`，未知或浮点型为空。这些统计不单独判定电极、ADC 或固件故障，也不触发停流。


高级设置默认目标 `192.168.4.1:80`、电脑数据监听端口 6677；回连网卡由到目标的系统路由选择，也可手动指定。设备提供热点及 HTTP 服务，数据由设备回连电脑。现有 BFSP TCP 地址入口不能代替此适配器。首版不在应用内扫描或切换系统热点，也不依赖 SSID/位置权限；系统 Wi-Fi 页面无法打开时提供手工连接提示。

连接失败、启动采集失败和采集期间中断分别显示。Wi-Fi 失败提示保留请求方法、接口与 HTTP 状态或超时结果；设备回连失败时显示实际监听地址/端口，并提示检查当前测试版应用的 Windows 防火墙入站权限。失败提示旁可“复制诊断信息”，复制错误码、请求阶段、状态/耗时和网络端点；TCP 配置失败还保留本次配置参数及有长度上限、敏感词过滤的拒绝原因，不复制设备状态响应全文、热点密码或信号数据。等待回连及首批数据的时限从对应 HTTP 请求接受后开始，避免覆盖请求本身的超时原因；配置与启动失败均不自动重发。

成功连接后自动保存非敏感配置到应用配置目录 `device-profiles.json`，最多 16 项，可在总览的“已保存的设备”中改名、重连或移除记录。移除记录仅更新本地保存配置，不断开当前连接、不停止采集。保存记录不表示在线，重连会重新核对；身份可用时将探测值约束到本次连接。文件损坏不阻塞启动，也不覆盖损坏原件。不会保存热点密码或自动接管报告已占用的连接。

BFSP TCP 与模拟器在“高级连接方式”中。TCP 填写地址、端口与可选身份约束，显式连接后才切换设备，打开设置不会断开已有空闲连接；模拟器连接同样自动显示波形。设备连接窗口不维护独立样式表，跟随主应用主题与语言。

RT-BCI 原始帧没有 CRC、硬件时间戳或前后 bank 标签。8 路接纳所有帧头/帧尾合规的包。重复包号保留原始字节警告，但不单独推断丢样、不生成缺口；坏帧丢弃或计数跳变仍记录未知缺口。重复号可能携带不同的有效样本或另一组通道，不能把它直接解释为数据中断，否则密集断点经极值抽稀会抹掉全部可绘制线段。16 路按参考规则，计数变化时缓存第一 bank，同计数的后续帧补充第二 bank 并立即发布；三次相同计数也按参考行为保留第一 bank、更新第二 bank 后发布。孤帧或不完整尾帧记日志后丢弃，不再结束采集。

录制与显示的样本索引使用 `adapter_received` 接收序号，不再将 8 位计数跨圈猜成设备时间，也不据此虚报精确丢样数。异常写入未知缺口事件，原始 ADC 数值不修改，时间仍为按所选名义速率估计。按参考规则接纳不代表 ADC 转换无丢样或通道配对已由硬件认证。


停流不清空设备内部缓存；起止边界、配置来源和计数含义写入录制元数据。停止采集时完整 16 路帧对已经发布，残余第一 bank 或不完整字节只记日志，末尾边界仍写入未知缺口事件，进行中的录制按未知尾部清算为 partial。独立停止录制仍可正常保存已接纳数据并继续采集。请求超时或断连会保留故障信息；本地关闭 socket 不等于远端停流/释放状态已验证。

## 本地模拟信号

设备连接窗口的“高级连接方式”提供模拟信号预设，默认“ICA 混合信号”。选择预设后使用模拟设备，采集自动开始；切换预设前停止采集与录制。

ICA 预设包含三路混合观测、一路眼电参考与一路肌电参考。信号由振荡、慢脉冲与高频突发三个数学源按固定矩阵合成，采用 `float32`、`uV`、单位增益。样本按时间连续生成，支持250/500/1000 Hz；固定模型连续ICA使用250/500 Hz。参考通道独立于拟合，进入分离页自动预填三路观测与两路参考，建模后可用“应用教学标记”对照分类。

“周期波形”保留四路原有 `int24` 信号，供采集与频谱检查。两个预设共用设备采集、SignalHub、原始录制和回放链路。ICA录制包含预设版本、通道用途与混合矩阵元数据；模拟标记、通道身份、单位和typed样本在回放中保留，回放信号可再次进入分离。

固定波形支持跨采样率与分块重现。数据用于功能验证与操作练习，生理效果需实验记录验证。

## 4. 独立 TCP 模拟器

在源码仓库根目录运行（Python 3.10+，仅标准库）：

```bash
python3 -m tools.bfsp_simulator --host 127.0.0.1 --port 45120
```

端口为本项目开发默认值，可用 `--port 0` 让系统分配。模拟器默认仅供本机开发，未实现远程 TLS/认证，不应被描述为已验收的公网设备网关。可用选项和故障注入以 `python3 -m tools.bfsp_simulator --help` 为准。

模拟器与 Native 编解码相互独立。正常流支持握手、配置回读、prepare/accept/start/stop、END 和心跳；故障注入用于启动响应丢失、无数据、CRC 损坏和缺口等回归。新增设备必须实现适配，不会因为使用某种连接方式就自动被识别。

## 4. ESP32 HTTP 独立诊断

日常使用 Windows 单文件一键诊断工具：连接设备热点后双击运行，自动读取状态、在设备明确空闲时执行一次参考格式的 TCP 连接测试，再将日志保存为一个 ZIP 并打开所在位置。无需 Python、命令行或选择模式；不启动 ADC 采集。遇到设备不可达、端口占用或已有会话时也保存结果。程序旁目录不可写时自动使用用户下载目录或临时目录；检查中关闭窗口会在后台完成当前有界检查并保存日志。

源码入口为 `tools/rt_bci_quick_diagnostic.py`，下列脚本参数仅供开发者进一步定位，不属于日常操作流程。

连接成功但采集中断时，可使用独立的“ESP32 一键采集诊断”工具（`tools/rt_bci_stream_diagnostic.py`）。关闭其他上位机并保持热点连接后双击运行，无需安装 Python 或填写参数。它只在 `/board` 明确报告 8 通道就绪且 `/tcp` 明确空闲时，按应用的连接流程执行预停流、一次 TCP 配置、一次 `~6`（250 Hz）命令和一次启动；短时接收约 3 秒后自动请求停流。启动响应超时也会尝试一次停流，不自动重发配置或启动。未确认停流时提示重启设备。

采集诊断 ZIP 包含 HTTP 交互、`stream.raw` 原始字节、TCP 分批到达时间及候选帧/计数统计；原始数据有 256 KiB 上限，不滤波、不修改数据、不推断另一种通道布局。候选扫描仅供定位，不能当作完整录制或 ADC 无丢样证明；诊断结束可能截断尾帧。工具关闭窗口后仍会在后台完成停流和日志保存。原连接诊断工具继续保持不启动 ADC 的行为。

当前接收兼容候选构建包含应用内异常日志；旧 `.7` 安装包仍采用严格解码与旧中断条件，不包含这些兼容修复。

`python tools/rt_bci_http_diagnostic.py` 使用 Python 3.10+ 标准库，只读查询 `/board`、`/tcp`、`/all`。结果写到脚本旁新建的 `ESP32-HTTP-*` 目录；结构化凭据字段会脱敏，不读取 ADC 信号。

`--test-tcp` 是显式 TCP 配置测试：先确认模块报告未连接，再监听电脑端口并只发送一次 `/tcp` 配置，不发采样率、开始或停止命令。默认 `--format reference` 采用参考 BrainFlow 的 HTTP/1.0、标准头字段大小写、Content-Length、无 Content-Type 的报文；`canonical` 使用 HTTP/1.1 和 application/json；`lowercase` 使用 HTTP/1.1 与小写字段。各次需手动执行，不会失败后自动重放。完成后关闭本地测试连接，模块可能保留最后的目标地址和端口。

`--proxy` 记录并转发用户在 OpenBCI 中实际发出的请求。脚本显示电脑的 Wi-Fi IPv4；在 OpenBCI 选择 Static IP 并将目标填为这个电脑地址，数据端口仍由 OpenBCI 自己监听。代理默认监听 80 端口，实际设备目标仍为 192.168.4.1。使用结束后在 OpenBCI 恢复设备 IP。代理会转发用户在 GUI 中发出的配置及启停指令；不会自行生成这些指令。

`http.jsonl` 分别记录 GUI 原始应用层请求和转发请求的方法、路径、HTTP 版本、头字段大小写、请求体及设备响应；转发时改写 Host 为设备地址。它不是 pcap，会改变 TCP 连接与分片/时序，不能当作被动抓包。代理仅接纳本机访问，接口有白名单与长度限制。当前代理针对 OpenBCI；不要用它替换 BoundFree 的目标地址，因为 BoundFree 还校验数据回连源 IP。

原 OpenBCI GUI 的 `Console_Data/Brainflow_*.txt` 日志也可查看配置字符串，但不保证记录完整 HTTP 头。ESP32 的 HTTP 服务实现仍需通过实际请求和响应核对，不能仅凭 JSON 解析错误断定某个参数错误。
